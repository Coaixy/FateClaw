  # Goal: 将用户自定义 Skill 全面迁移为现代 Markdown Skill Bundle 编辑器

  ## 背景

  当前用户自定义 Skill 已经在 runtime 和存储层部分迁移为 request-scoped Markdown Skill Bundle：DB 通过 `bundle_uri/
  checksum/install_status` 指向实际 bundle，agent runtime 读取 `SKILL.md` 和同目录 Markdown 文件。

  但 Web 创建/编辑流程、API DTO、DB schema 仍保留旧的“知识库 + 路由字段”模型，例如：

  - category / category_normalized
  - usage_mode
  - match_keywords
  - match_patterns
  - example_queries
  - priority
  - trigger_hint
  - 单一 content 编辑心智

  这些字段不属于现代 `SKILL.md` 的核心设计，应从用户 Skill 创建/编辑、API contract、runtime 查询和数据库 schema 中清
  理。

  ## 目标

  把 Studio Skill 创建/编辑改造成真正的 Skill Bundle 编辑器：

  - 用户编辑的是一个虚拟文件系统中的 Markdown bundle。
  - `SKILL.md` 使用结构化 Form 编辑核心 frontmatter 和入口说明。
  - 其他 `.md` 文件使用 Markdown 编辑器编辑。
  - 数据库只保存平台运行所需 metadata 和 bundle 指针，不再保存旧路由字段。
  - Runtime 只基于 `bundle_uri` 加载 request-scoped Skill，不再读取旧 category/usage/matching 字段。

  ## 目标后的核心模型

  ### Skill Bundle 文件

  每个用户 Skill 至少包含：

  - `SKILL.md`
  - `index.md`
  - `docs/knowledge.md`

  可选包含：

  - `docs/*.md`
  - `examples/*.md`
  - `notes/*.md`

  ### `SKILL.md` Form 字段

  `SKILL.md` 的结构化 Form 只包含真正属于 Skill 文件的内容：

  - `name`
  - `description`
  - 入口说明 / 使用边界
  - 推荐读取顺序 / 文件索引说明

  不包含：

  - category
  - usage_mode
  - match_keywords
  - match_patterns
  - example_queries
  - priority
  - trigger_hint

  ### 平台 metadata

  DB 保留平台字段：

  - id
  - user_id
  - skill_name 或 display_name
  - dir_name
  - version
  - bundle_uri
  - checksum
  - install_status
  - acl
  - billing_policy
  - audit_metadata
  - visibility
  - share_token
  - enabled
  - price_tiers
  - stat_subscriber_count
  - stat_view_count
  - created_at / updated_at / deleted_at

  `skill_name/description` 如仍需列表展示，应从 `SKILL.md` frontmatter 同步为 denormalized cache，而不是作为独立编辑
  源。

  ## 数据库清理

  新增 migration：

  1. 迁移现有旧字段数据到 bundle 文件中：
     - 如果 `trigger_hint` 有值，写入或追加到 `SKILL.md` 的入口说明区域。
     - 现有 `content` 已迁移到 `docs/knowledge.md` 的继续沿用。
     - `category/usage_mode/match_keywords/match_patterns/example_queries/priority` 不再迁移为独立字段；如确有历史可读
  价值，可写入 `notes/legacy-routing.md`，否则直接丢弃。

  2. 从 `user_custom_skills` 删除旧字段：
     - `trigger_hint`
     - `category`
     - `category_normalized`
     - `match_keywords`
     - `match_patterns`
     - `example_queries`
     - `priority`
     - `usage_mode`

  3. 删除相关约束、索引、默认值和历史迁移中的兼容逻辑。

  4. 更新所有 shared types / contract DTO / repository row mapping。

  ## API 重构

  替换当前 `POST /api/skills/user` 和 `PUT /api/skills/user/:id` 的旧 payload。

  ### 新创建请求

  ```ts
  type CreateUserSkillRequest = {
    skill_name: string;
    dir_name?: string;
    files: Array<{
      path: string;
      content: string;
    }>;
  };

  ### 新更新请求

  type UpdateUserSkillRequest = {
    skill_name?: string;
    files?: Array<{
      path: string;
      content: string;
    }>;
  };

  后端负责：

  - 校验 path 只能是安全相对路径。
  - 只允许 .md 文件。
  - 禁止 ..、绝对路径、隐藏危险路径。
  - 确保存在 SKILL.md。
  - 从 SKILL.md frontmatter 同步 name/description。
  - 写 bundle 文件。
  - 计算 checksum。
  - 更新 bundle_uri/checksum/install_status。

  ## Web 重构

  删除当前基于 SkillFormData.content/category/usage_mode/match_keywords 的创建方式。

  新增 Skill Bundle Editor：

  ### 布局

  左侧文件树：

  SKILL.md
  index.md
  docs/
  examples/
  notes/

  右侧编辑区：

  - 选中 SKILL.md：显示结构化 Form，并提供“查看 Markdown 原文”。
  - 选中其他 .md：显示 Markdown 编辑器和预览。
  - 支持新增文件、重命名文件、删除文件、创建目录。

  ### 创建页

  apps/web/app/studio/skills/new/page.tsx 改为打开 Bundle Editor。

  默认新建模板：

  - SKILL.md
  - index.md
  - docs/knowledge.md

  ### 编辑页

  apps/web/app/studio/skills/edit/page.tsx 不再只加载 content，而是加载完整 bundle files。

  ### Studio / Discover / Admin UI

  移除以下展示和筛选：

  - category badge
  - usage_mode badge
  - match_keywords 展示
  - category filter

  如市场后续需要分类，另起独立 tags 或 market_category 设计，不复用旧字段。

  ## Runtime 重构

  更新 agent runtime skill 查询：

  - EffectiveUserSkill 移除 category / category_normalized / match_keywords / match_patterns / example_queries /
    priority / usage_mode / trigger。
  - DB query 只读取：
      - id
      - dir
      - name
      - description
      - bundle_uri
      - checksum
      - install_status
      - visibility
      - source

  更新 resource loader：

  - 不再拼接 category=...。
  - 不再拼接 usageMode=...。
  - 只暴露 request-scoped Markdown Skill Bundle。
  - append prompt 只列出 skill name 和 description。

  ## Repository / Storage 重构

  重构 text-skill-bundle-store：

  - 从只写 docs/knowledge.md 改为支持完整 files 写入。
  - 增加 readTextSkillBundleFiles(bundle_uri)。
  - 增加 writeTextSkillBundleFiles(input)。
  - 保留安全路径校验。
  - checksum 基于所有 bundle 文件内容计算。
  - 编辑保存时整体替换或事务化写入 bundle。

  ## 测试要求

  补充或更新测试：

  1. 创建 Skill Bundle：
      - 写入 SKILL.md/index.md/docs/knowledge.md
      - DB 写入 bundle_uri/checksum/install_status
      - 不再写旧路由字段
  2. 更新 Skill Bundle：
      - 修改文件后 checksum 变化
      - 删除文件后读取结果正确
      - 非法 path 被拒绝
  3. Runtime：
      - request-scoped skill 能从 bundle_uri 加载
      - prompt 不再包含 category/usageMode
      - 旧字段从 EffectiveUserSkill 类型移除
  4. Web：
      - 新建页提交 files payload
      - 编辑页能回显完整文件树
      - SKILL.md Form 和 Markdown 内容同步正确
  5. Contract：
      - 前后端 DTO 不再暴露 category / usage_mode / match_keywords / match_patterns / example_queries / priority /
        trigger_hint

  ## 非目标

  - 不实现新的 tags / market_category 系统。
  - 不实现复杂权限文件系统。
  - 不支持非 Markdown 文件。
  - 不改变官方排盘 skill、盘面 category、evidence category 等非用户 Skill Bundle 业务字段。

  ## 验收标准

  - 用户可以在 Studio 中创建、编辑、保存一个完整 Markdown Skill Bundle。
  - SKILL.md 由 Form 安全编辑，其他 .md 文件可自由 Markdown 编辑。
  - DB schema 不再包含旧用户 Skill 路由字段。
  - API contract 不再要求或返回旧路由字段。
  - Agent runtime 正常加载用户自建和订阅的 request-scoped Skill Bundle。
  - 现有 market/share/subscribe/bundle 功能在新模型下仍可工作。

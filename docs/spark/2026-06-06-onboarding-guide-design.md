# FateClaw 启动向导设计

日期：2026-06-06

## 背景

当前用户进入 Web AI Chat 后，容易卡在两个前置环节：

- 不知道需要先配置模型，导致无法开始对话。
- 不知道如何配置或启用 Skill，导致知识库能力无法进入主链路。

本设计目标是降低首次使用成本，让用户完成“标准可用”状态：已可使用官方模型，并至少启用 1 个可用于对话的 Skill，然后回到 AI Chat 开始提问。

## 目标

启动向导要完成以下事情：

- 在 `/ai-chat` 首次进入时识别用户是否缺少模型或 Skill。
- 用轻量弹层解释接下来只需完成两步：选择官方模型、安装并启用一个 Skill。
- 将用户带到现有模型配置入口和 Skill 市场完成真实操作。
- 用户跳转回来后可以继续向导，不从头开始。
- 两项都完成后，引导用户开始第一次 AI Chat。

## 非目标

本次不做以下内容：

- 不做强制阻塞式配置流程。
- 不做多页面浮层高亮教程。
- 不做完整教程系统、任务系统或用户成长体系。
- 不引导用户自配 API Key、Base URL、Provider 等高级模型参数。
- 不重做模型设置页、Skill 市场或 Skill 编辑器。

## 推荐方案

采用“首次轻量向导弹层 + 可跳转续接”方案。

用户进入 `/ai-chat` 后，前端检查模型和 Skill 状态。如果缺少任一项，并且用户本次未主动关闭过向导，则弹出启动向导。向导本身不承载复杂表单，只负责说明、判断、跳转和恢复。真实配置仍发生在现有模型设置页和 Skill 市场。

这个方案比阻塞式配置更温和，也比纯空状态清单更明确，适合当前“用户不知道怎么开始”的问题。

## 用户旅程

### 入口触发

启动向导只在 `/ai-chat` 作为主入口触发。

触发条件：

- 用户未满足 `modelReady`。
- 或用户未满足 `skillReady`。
- 且当前浏览器 session 内未主动关闭过向导。

不触发条件：

- 用户已有可用官方模型，并且至少启用 1 个可用于对话的 Skill。
- 用户本次 session 已主动关闭向导。
- 当前正在展示全站“用前须知与隐私说明”弹窗。

### 步骤

向导包含 4 个步骤：

1. 欢迎页：说明“完成两步后即可开始使用：选择官方模型、安装一个 Skill”。
2. 官方模型页：引导用户使用官方模型优先路径。
3. Skill 页：引导用户进入 Skill 市场，自行选择并安装一个 Skill；如果安装后未默认启用，则继续引导用户启用它。
4. 完成页：回到 AI Chat，提供“开始提问”按钮和可选示例问题。

### 跳转与续接

当用户点击“去选择官方模型”或“去 Skill 市场”时：

- 前端保存当前向导步骤到 `sessionStorage`。
- 跳转时带上返回信息，例如 `returnTo=/ai-chat&guide=resume`。
- 用户完成操作并回到 `/ai-chat` 后，重新检查模型和 Skill 状态。
- 如果当前步骤已完成，自动推进到下一步。
- 如果仍未完成，停留在当前步骤并提示“还差一步”。

## 界面设计

启动向导使用轻量弹层，不使用复杂后台表单。

结构：

- 顶部：步骤点或简短进度条，展示 `欢迎 -> 官方模型 -> Skill -> 完成`。
- 中部：当前步骤说明和状态卡片。
- 底部：主按钮和次按钮。

按钮文案：

- 欢迎页：`开始配置`
- 官方模型未完成：`去选择官方模型`
- 官方模型已完成：`下一步`
- Skill 未完成：`去 Skill 市场`
- Skill 已完成：`完成`
- 完成页：`开始提问`

视觉风格沿用现有 FateClaw 前端：暖纸面背景、珊瑚主按钮、轻边框卡片、克制动效。它应该像一个清楚的启动提示，而不是营销页或大段教程。

## 状态模型

前端维护 3 类状态：

- `modelReady`：当前用户是否已有可用官方模型配置或已选择官方模型。
- `skillReady`：当前用户是否至少有一个已启用、可用于对话的 Skill。
- `guideDismissed`：用户本次 session 是否主动关闭过向导。

状态来源：

- `modelReady` 优先复用现有 model settings API。
- `skillReady` 复用现有 `skillsApi.userList()`，检查 own 或 subscribed 中是否存在 enabled 项；仅安装但未启用不算完成。
- `guideDismissed` 存在 `sessionStorage`，只影响本次浏览器 session。

完成状态不额外写入后端，因为它可以由模型状态和 Skill 状态推导。

## 组件边界

建议新增以下前端单元：

- `OnboardingGuideDialog`：展示弹层、步骤、按钮和状态说明。
- `useOnboardingGuideStatus`：读取模型状态、Skill 状态、sessionStorage，并推导当前步骤。

建议接入位置：

- `/ai-chat` 工作区负责触发和展示向导。
- 模型设置页和 Skill 市场仅需要支持返回参数或返回按钮。

不建议让向导直接修改模型或 Skill 数据。它应调用现有页面完成真实操作，避免形成第二套配置入口。

## 异常与兜底

### 模型侧

- 官方模型状态加载失败时，显示“暂时无法读取官方模型”，提供 `稍后重试` 和 `跳过本次`。
- 没有可用官方模型时，显示“当前暂无可用官方模型，请联系管理员”，不引导用户填写复杂 API Key。
- 用户进入模型页后未完成就返回时，向导停留在官方模型步骤。

### Skill 侧

- Skill 市场加载失败时，显示“Skill 市场暂时不可用”，提供 `稍后重试`。
- 用户进入 Skill 市场但未安装或启用就返回时，向导停留在 Skill 步骤。
- 用户已安装但未启用时，向导提示“已安装，需启用后才能用于对话”。

### 不打扰规则

- 用户关闭弹层后，本次 session 不再自动弹出。
- AI Chat 空状态保留“继续完成启动向导”入口。
- 用户完成模型和 Skill 后，后续不再显示向导。

### 合规弹窗顺序

现有“用前须知与隐私说明”弹窗优先出现。启动向导应等用户同意后再出现，避免两个弹层叠加。

## 验证计划

单元测试覆盖：

- 未配置模型且未启用 Skill 时打开向导。
- 已配置模型但未启用 Skill 时进入 Skill 步骤。
- 已配置模型且已启用 Skill 时不打开向导。
- 用户关闭向导后，本次 session 不再自动弹出。
- 用户从模型设置页返回后，向导重新检查状态并推进。
- 用户从 Skill 市场返回后，向导重新检查状态并推进。

手工走查覆盖：

- 首次进入 `/ai-chat`。
- 关闭弹层后空状态入口仍可继续。
- 选择官方模型后返回 AI Chat。
- 进入 Skill 市场安装或启用 Skill 后返回 AI Chat。
- 完成后点击“开始提问”。
- 全站合规弹窗和启动向导不会同时显示。

建议验证命令：

```bash
pnpm --filter fateclaw-web exec tsc --noEmit
pnpm --filter fateclaw-web build
```
